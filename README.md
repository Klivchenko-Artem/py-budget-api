# Учёт личных финансов: API на FastAPI

Асинхронный REST-сервис: доходы и расходы по категориям, бюджеты на месяц
и отчёт, который считает база, а не питон. Токенная авторизация, PostgreSQL,
миграции alembic, кеш отчётов в Redis, тесты на pytest, всё поднимается одной
командой.

Стек: FastAPI + Pydantic v2, SQLAlchemy 2.0 в асинхронном режиме поверх asyncpg,
alembic, Redis, Docker Compose.

## Как устроено

```
app/main.py        приложение: маршруты, перевод ошибок в коды, /healthz и /readyz
app/api            HTTP-слой: зависимости запроса и ручки
app/services       прикладная логика, не знает про HTTP; кеш дёргает
                   через app/core/cache, сам про Redis не знает
app/db             модели и подключение к базе
app/schemas        схемы запросов и ответов
app/core           настройки, пароли и токены, ошибки предметной области, кеш
alembic            миграции
tests              41 тест на pytest
```

Слои разделены: ручка разбирает запрос и отдаёт ответ, сервис знает правила,
модели знают про таблицы. Про Redis знает только `app/core/cache`: сервисы
зовут `cache.drop_later`, а какой там клиент и что делать, когда он не отвечает,
решается в одном месте. Сервисы не бросают `HTTPException`, они бросают
собственные ошибки (`NotFoundError`, `AlreadyExistsError`, ...), а перевод
в коды ответа лежит одним словарём в `app/main.py`.

Что стоит посмотреть:

- Отчёт считается в базе (`app/services/reports.py`), суммы и количество
  по категориям берутся групповым запросом, а не циклом по выборке. Разница
  видна на второй год использования, когда операций становятся тысячи.
- Точечный сброс кеша (`app/services/operations.py`), при правке операции
  сбрасываются отчёты обоих месяцев: старого и нового, потому что операция
  могла переехать. При удалении категории, все отчёты пользователя.
- Деньги хранятся в `Numeric`, а не `float` (`app/db/models.py`) и уезжают наружу
  строкой (`app/schemas/common.py`): `0.1 + 0.2` в двоичной дроби не равно
  `0.3`, и на отчётах это вылезает копейками расхождения.
- Вид операции берётся из категории, клиент не может записать трату
  в категорию доходов, потому что вид не спрашивается вообще.

## Запуск

```bash
docker compose up -d
```

Поднимаются сервис, PostgreSQL и Redis. Миграции накатываются в `entrypoint.sh`
до старта uvicorn, иначе первый же запрос уткнулся бы в отсутствующие таблицы.

| Что | Где |
| --- | --- |
| API | http://localhost:8000 |
| Документация Swagger | http://localhost:8000/docs |
| Схема OpenAPI | http://localhost:8000/openapi.json |

Порты подвигаются переменными: `HTTP_PORT=8001 POSTGRES_PORT=5435 docker compose up -d`.
Без Docker: заполнить окружение по `.env.example`, `alembic upgrade head`
и `uvicorn app.main:app`.

## API

| Метод | Путь | Что делает |
| --- | --- | --- |
| `POST` | `/api/auth/register` | регистрация, сразу отдаёт токен |
| `POST` | `/api/auth/login` | вход |
| `GET` | `/api/auth/me` | кто я |
| `POST` | `/api/categories` | завести категорию (`income` или `expense`) |
| `GET` | `/api/categories` | свои категории, фильтр `kind` |
| `PATCH` | `/api/categories/{id}` | переименовать |
| `DELETE` | `/api/categories/{id}` | удалить вместе с операциями |
| `POST` | `/api/operations` | записать трату или поступление |
| `GET` | `/api/operations` | список: `kind`, `category_id`, `date_from`, `date_to`, `limit`, `offset` |
| `PATCH` | `/api/operations/{id}` | поправить |
| `DELETE` | `/api/operations/{id}` | удалить |
| `PUT` | `/api/budgets` | поставить лимит на категорию и месяц |
| `GET` | `/api/budgets` | лимиты за месяц (`month=2026-09`) |
| `DELETE` | `/api/budgets/{id}` | снять лимит |
| `GET` | `/api/reports/monthly` | отчёт за месяц |
| `GET` | `/healthz`, `/readyz` | живость и готовность |

Всё, кроме регистрации, входа и служебных ручек, требует заголовка
`Authorization: Bearer <токен>`.

```bash
# регистрация
curl -X POST localhost:8000/api/auth/register \
  -H 'Content-Type: application/json' \
  -d '{"email":"me@example.com","password":"supersecret1"}'

# категория и трата
curl -X POST localhost:8000/api/categories \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"name":"Еда","kind":"expense"}'

curl -X POST localhost:8000/api/operations \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"category_id":1,"amount":"1500.50","occurred_on":"2026-09-06","note":"продукты"}'

# лимит на месяц и отчёт
curl -X PUT localhost:8000/api/budgets \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"category_id":1,"month":"2026-09","limit_amount":"20000.00"}'

curl -H "Authorization: Bearer $TOKEN" 'localhost:8000/api/reports/monthly?month=2026-09'
```

Ответ отчёта:

```json
{
  "month": "2026-09",
  "income": "120000.00",
  "expense": "2750.50",
  "balance": "117249.50",
  "by_category": [
    {"category_id": 2, "category_name": "Еда", "kind": "expense", "total": "2300.50", "operations": 2}
  ],
  "budgets": [
    {"category_name": "Еда", "limit_amount": "2000.00", "spent": "2300.50",
     "left": "0.00", "used_percent": 115.0, "exceeded": true}
  ]
}
```

## Решения, которые стоит объяснить

- Вход не проверяет длину пароля. Требование «не короче восьми» на `/login`
  выдало бы 422 вместо 401 и заодно рассказало бы подбирающему пароль про нашу
  политику. На регистрации проверка есть.
- Неизвестная почта и неверный пароль отвечают одинаково. Иначе по коду
  ответа собирается список зарегистрированных адресов.
- Чужая запись отвечает «не найдено», а не «нет доступа». Иначе по коду
  ответа можно проверять, что заведено у соседа.
- Бюджет ставится через `PUT`, а не `POST`. Переставить лимит это обычное
  дело, а не создание второй сущности; уникальность держит база.
- Остаток по бюджету не уходит в минус. Перерасход виден по флагу
  `exceeded`, а «сколько ещё можно потратить» ниже нуля не бывает.
- Ошибки Redis не всплывают наверх. Кеш ускоряет, но не является источником
  правды: его недоступность не должна ронять API.
- `/healthz` и `/readyz` отвечают на разные вопросы. Живость про сам процесс: если
  проверять в ней базу, моргнувший Postgres перезапустит все поды разом.
  Готовность проверяет зависимости и называет, что именно легло.
- Пустое примечание и «не трогай примечание» различаются по `model_fields_set`,
  иначе любая правка суммы затирала бы комментарий.

## Тесты

```bash
make test      # pytest в контейнере
make lint      # ruff
```

41 тест: регистрация и вход (включая нормализацию почты и одинаковый ответ на
неизвестную почту), права на чужие записи, уникальность категорий, фильтры и
пагинация операций (`total` считается по фильтру, а не по странице), суммы
в отчёте, исполнение и перерасход бюджета, кеш, что он появляется, что отчёт
из него совпадает и что он сбрасывается при любой правке денег, в том числе при
переносе операции в другой месяц.

CI гоняет ruff, накатывает миграции на чистую базу, откатывает их до нуля
и накатывает снова, потом прогоняет тесты.

Грабля, которая стоила базы. Тесты берут отдельную базу и отдельный номер
базы Redis, и выбираются они принудительно, а не через `os.environ.setdefault`:
в контейнере `DATABASE_URL` уже указывает на рабочую базу, мягкая подстановка
её оставила бы, а тесты в конце сносят всю схему. Ровно так один раз и вышло.
Теперь `conftest.py` сам дописывает суффикс `_test`, если его нет.

## Чего здесь намеренно нет

- Синхронного SQLAlchemy. Смысл FastAPI в асинхронности; смешивать её
  с блокирующим драйвером означает держать пул потоков ради тех же запросов.
- Refresh-токенов. Один короткоживущий токен закрывает задачу, а полноценная
  сессия с ротацией это отдельная история, которую нечестно изображать наполовину.
- Общего слоя репозиториев. При четырёх таблицах он был бы папкой из файлов,
  каждый из которых пересказывает `session.scalar` своими словами.
